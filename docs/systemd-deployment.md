# Запуск через systemd

Сервис рассчитан на Linux amd64 с локальным PostgreSQL и systemd. Сборка
выполняется на машине разработчика; Go и Git на сервере не требуются.

## Разовая подготовка

- Создать системного пользователя и группу `weather-sum` без shell.
- Создать отдельную БД `weather_bot`. В ней выполнить `scripts/db-roles.sql`,
  задать уникальные пароли для `weather_app` и `weather_migrator`.
  Роли не должны использоваться другими приложениями.
- Установить Goose v3.27.2 в `/usr/local/lib/weather-sum/goose`.
- Создать каталог `/etc/weather-sum` с правами `700`, владелец root.
- В `/etc/weather-sum/app.env` записать `TELEGRAM_BOT_TOKEN`, `DATABASE_URL`
  с ролью `weather_app`, дополнительные погодные ключи и настройки приложения.
  Формат — `EnvironmentFile` systemd; значения со пробелами заключать в кавычки.
- В `/etc/weather-sum/migrate.env` записать `GOOSE_DRIVER=postgres` и
  `GOOSE_DBSTRING` с ролью `weather_migrator`. Файл читается Bash, поэтому
  строку подключения заключать в одинарные кавычки.
- У обоих файлов права `600`, владелец root. Секреты не копируются в релизы
  и не хранятся в Git. PostgreSQL должен слушать только локальные интерфейсы.

Для локального PostgreSQL строки подключения имеют хост `127.0.0.1`, порт
`5432`, базу `weather_bot`; специальные символы пароля кодируются для URI.
Реквизиты локальной базы разработки на сервер не переносятся.

## Деплой и обновление

Из чистой рабочей копии после коммита и push:

```bash
bash scripts/deploy-systemd.sh root@155.212.164.198
```

Скрипт собирает статический бинарник, передаёт только бинарник, миграции и файлы
установки в `/opt/weather-sum/releases/<дата>-<коммит>`, останавливает бот,
применяет миграции отдельной ролью, выдаёт права и переключает `current`.
Затем включает автозапуск, запускает сервис и проверяет `/healthz`.
При ошибке миграций деплой останавливается; схема автоматически не откатывается.
Приложение работает без root, с файловой системой, доступной только для чтения.

Автоматические резервные копии для этой установки по решению владельца
не настраиваются. Скрипт обновления также не создаёт backup.

## Управление

```bash
ssh root@155.212.164.198 'systemctl status weather-sum --no-pager'
ssh root@155.212.164.198 'journalctl -u weather-sum -n 50 --no-pager'
ssh root@155.212.164.198 'systemctl restart weather-sum'
ssh root@155.212.164.198 'curl --fail http://127.0.0.1:8080/healthz'
```

`Restart=always` перезапускает завершившийся процесс с задержкой 10 секунд.
`systemctl stop weather-sum` останавливает его до следующего запуска или
перезагрузки. Для отключения автозапуска использовать `systemctl disable --now
weather-sum`. Сам healthcheck не является watchdog и не перезапускает зависший
процесс. Изменение ключей требует рестарта сервиса.

Один бот должен работать в одном экземпляре. Локальная копия с тем же токеном
не должна одновременно опрашивать Telegram. Публичный HTTP-порт и домен боту
не нужны: Telegram используется через исходящий long polling.
